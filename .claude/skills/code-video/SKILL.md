# code-video: 코드로 감도 높은 영상 만들기

출처: 공여사들 〈클로드 코드로 감도높은 영상 만드는 법〉 (https://youtu.be/FqERJgZSLUo)
※ 기본 구조는 영상 설명란·챕터·키워드 기반이고, 아래 '실제 피드백 패턴'·'제작 구조'·'모델 전략'은 사용자가 제공한 자막 요약을 반영함.

## 핵심 원리
- AI는 텍스트만 다루지만 웹사이트를 **코드**로 만들 수 있고, 그 화면을 **프레임 단위로 렌더링**하면 영상이 된다.
- 도구: **Remotion**(React) 또는 **HyperFrames**(HTML 기반). 생성형 영상(실사)이 아니라 **코드형 영상**(모션그래픽, UI 화면, 인포그래픽)에 적합.
- 결과물 품질 = 지시의 질. **"예쁘게 만들어줘"는 통하지 않는다.** AI가 생각하는 "예쁨"은 촌스럽다.

## 워크플로
1. **브리프 확인**: 목적, 길이, 비율(16:9 / 9:16), 톤, 대상. 모자라면 한 번에 묻는다.
2. **브랜드 자산 수집** (가장 중요)
   - 브랜드 컬러(HEX), 폰트, 로고 파일. 컬러만 지정해도 AI 티가 크게 줄어든다.
   - **로고는 만들지 말고 반드시 다운로드/제공받아 사용** (AI가 그린 로고는 틀린다).
   - 디자인 가이드(md)가 있으면 읽고 토큰(색/타입/간격/그림자)으로 고정.
3. **참고 화면 재현**: 노션·카카오톡 등 실제 UI가 나오면 스크린샷을 레퍼런스로 받아 레이아웃·색·폰트·말풍선 모양을 **똑같이** 구현. 상상으로 그리지 않는다.
4. **씬 설계**: 씬 목록(번호, 길이, 화면 요소, 모션, 자막/나레이션)을 표로 먼저 제시하고 승인받는다.
5. **구현**: 씬마다 컴포넌트 분리, 공통 토큰(`theme.ts`)에서 색·폰트·이징 참조. 하드코딩 금지.
6. **프리뷰 → 피드백 → 수정**: 씬별로 짧은 피드백 1줄씩 반영. 확정 후 MP4 렌더.
7. **재사용**: 반복 작업은 스킬/템플릿으로 굳혀 매번 같은 품질을 낸다.

## 지시(프롬프트) 원칙 — "이유를 함께 준다"
- 짧은 지시여도 **이유**를 붙이면 의도를 이해한다.
  - 나쁨: "글자 줄여"
  - 좋음: "글자가 많으면 시청자가 읽다가 말을 놓친다. 한 화면에 핵심 단어 하나만."
- 피드백은 영상 한 편당 한두 줄씩 구체적으로 (무엇이 / 왜 / 어떻게).
- 한 번에 크게 갈아엎지 말고 씬 단위로 고친다.

## 실제 피드백 패턴 (프롬프트는 1~4줄, 이유를 붙인다)
이유/맥락을 함께 주면 후반 피드백(20~30번째 영상)에서도 원칙이 유지된다.
- **텍스트 범벅 제거**: "글자가 너무 많다. 사람은 그림을 잘 이해한다. 텍스트를 아이콘이나 이미지로 바꿔라."
- **아이콘으로 퉁치기**: "신청 게시물은 텍스트 대신 발행 이모티콘", "블로그 초안은 노션 아이콘", "뉴스레터는 글자 대신 스티비 아이콘".
- **AI 슬롭 억제**: 불필요한 라벨, 숫자 배지(1,2,3), 태그 박스를 붙이지 말고 정갈한 UI 유지.
- **시선 중심점**: 초반에 애플 광고처럼 검은 배경+흰 글자로 시선을 중앙에 모은 뒤 전개. 요소를 좌우에 무분별하게 흩뿌리지 않는다.
- **자막 없이 검증**: 자막을 끄고 봐도 행동·흐름이 읽혀야 한다. 안 읽히면 실패한 씬.
- **이름 붙여 고정**: 로직/컴포넌트에 고유 이름(예: `capbox-video-reg`)을 붙여 두고 "이걸 써라"라고 지시하면, AI가 새 스크립트를 만들지 않고 그대로 재사용한다.

## 제작 구조
- 스택: Remotion/HyperFrames + React → 렌더(웹 녹화 방식)로 영상 출력.
- **자막 데이터를 단일 진실 공급원(SSOT)** 으로 두고, 자막 타임스탬프로 타임라인을 분절해 씬을 배치한다.
- **SVG 아이콘/로고**: 확대해도 깨지지 않으므로 다운로드해 사용. 자주 쓰는 로고·UI(카톡, 노션, 캘린더 등)는 로컬 폴더(`assets/logos/` 등)와 템플릿으로 자산화해 토큰 비용을 줄인다.

## 모델 전략 (비용 vs 효율)
- **초기 구축**: 상위 모델로 복잡한 템플릿·컴포넌트를 한 번 제대로 만든다.
- **반복 생산**: 템플릿이 완성되면 저렴한 모델로 파라미터(텍스트, 시간, 아이콘)만 넘겨 영상 생성.

## 모션그래픽 프롬프트 패턴 (두 번째 영상: Opus 5.5 모션그래픽)
- **쇼릴 지시문**: "15초짜리 역동적인 모션 그래픽 영상을 만들어 줘. 네가 얼마나 대단한 모션 디자이너인지를 보여주는 이력서 첨부용 쇼릴처럼, 할 수 있는 건 다 쏟아부어."
- **레퍼런스 분석 지시문**: "아래 링크는 [서비스명]이야. 첨부한 [레퍼런스 영상 링크]를 참고해서 30~40초 모션 그래픽 소개 영상을 만들어 줘. 레퍼런스에서 어떤 부분을 왜 참고할지, 영상과 음악을 어떤 방향으로 기획할지도 같이 설명해 줘." → 구현 전에 기획 설명을 먼저 받고 승인한다.
- **트랜지션**: 깜빡임(플리커) 위주 전환은 피하고, 오브젝트가 축소/확대되며 다음 챕터 텍스트로 이어지는 서사형 전환을 요구한다.
- **키네틱 타이포**: 단어 의미와 모션을 일치시킨다 (예: spin=회전, guess=흔들림, consistency=글자가 합쳐짐).

## 리소스
- 레퍼런스 수집: keyframe.gallery (SaaS 앱 데모·웹 소개 영상).
- 음악/사운드: ElevenLabs 커넥터를 Claude Code에 연결해 영상의 기승전결(점입가경)에 맞춘 사운드트랙을 생성·연동.
- 기존 모션그래픽 코드/레퍼런스 모음(GitHub 등) 링크를 Claude에 주고 결합 연출을 유도.

## 디자인 원칙 (AI에게도 동일)
- 텍스트 과다 금지: 한 씬에 메시지 1개, 큰 타이포.
- 정렬·여백·위계 일관성, 색은 브랜드 팔레트 + 포인트 1색.
- 모션: 이징(ease-out 위주)과 타이밍에 리듬, 요소가 날아다니는 그래픽은 의미 있을 때만.
- 라이트/다크 씬 리듬, 그림자·곡률·폰트 규칙을 통일.
- "AI스러운" 징표 제거: 과한 그라디언트, 이모지 남발, 의미 없는 아이콘, 글자 가득한 화면.

## 흔한 실패와 점검표
- [ ] 로고/아이콘이 실제 파일인가
- [ ] 브랜드 컬러·폰트가 토큰으로 적용됐나
- [ ] 한 화면 텍스트가 과하지 않은가
- [ ] 실제 UI(노션/카톡 등)와 같은 모양인가
- [ ] 자막·나레이션과 화면 타이밍이 맞는가 (오디오는 별도 TTS/녹음, 싱크 확인)
- [ ] 해상도·fps·비율 확인 (기본 1920x1080 30fps / 숏폼 1080x1920)

## 기술 메모
- Remotion: `npx create-video@latest` → `npx remotion studio`(프리뷰) → `npx remotion render <Comp> out.mp4`.
- HyperFrames: HTML/CSS/JS 씬을 프레임 캡처해 렌더.
- 렌더에는 ffmpeg/Chromium 필요. 클라우드 환경에서는 Playwright 내장 Chromium 경로 사용.
- 코드형 vs 생성형: 정확한 텍스트·UI·브랜드는 코드형, 실사·자연스러운 움직임은 생성형(Higgsfield 등). 목적에 맞게 혼합.

## 함정
- 수정 지시가 모호하면 같은 실수를 반복한다 → 이유와 기준을 명시.
- 빠르다고 검수를 생략하지 말 것: 오탈자, 로고, 숫자, 타임라인.
- 작업 시간 대부분은 **자산 준비와 피드백**이다. 지시를 전날 던져두고 다음날 15분 피드백하는 식으로 운영 가능.

## 대사가 있는 쇼츠(9:16) 뉴스 영상 파이프라인 (showreel/ 구현 참고)
1. **팩트 확정**: 오늘 날짜 기사로 수치를 2곳 이상 교차 확인. 확인 못 한 수치는 대사/화면에서 뺀다. 출처를 장면 하단에 표기.
2. **대본**: `scripts/dialogue/<id>.json` (화자 A/B, 장면 번호, 표시용 텍스트). 대사는 핵심만, 세부 수치는 화면으로. 한 줄은 자막 3줄 이내.
3. **음성 합성(오프라인)**: sherpa-onnx + Supertonic 3 (`sherpa-onnx-supertonic-3-tts-int8-2026-05-11`, GitHub releases/tts-models에서 다운로드). 화자 스타일 0(여성 음역)·6(남성 음역). Mimic3 KSS는 명료도가 낮아 쓰지 않는다.
4. **한글 읽기 변환**: `scripts/ko_text.py` — 숫자·%·영문 약어를 한글 읽기로 바꿔 합성(화면 자막은 원문 그대로).
5. **자동 품질관리**: 한국어 ASR(`sherpa-onnx-streaming-zipformer-korean-2024-06-16`)로 각 대사를 N회 합성해 가장 가까운 후보를 선택(`build_voice.py`). 사람이 듣기 전 1차 검증일 뿐, 최종은 직접 들어볼 것.
6. **타임라인은 음성에서 도출**: 대사 길이 → 장면 길이, 전체 50초에 맞게 속도 자동 보정(0.85~1.2). 대사별 프레임 음량(env)을 JSON에 저장해 아바타 립싱크에 사용.
7. **화면(쇼츠 UI 안전영역, 1080x1920 기준)**: 상단 150px, 우측 x>920(y 815~1700, 좋아요·공유 버튼), 하단 y>1290(채널명·제목)은 비운다. 핵심 콘텐츠는 y 230~1230 안에 둔다. 자막은 대사를 구/절 단위(1~2줄, 28자 이내)로 쪼개 60px 이상 굵은 글씨 + 반투명 어두운 패널로 보여주고, 읽기 전 단어도 흐리게(투명도 0.35 이하) 하지 않는다. 보조 글씨는 최소 26~28px. 실제 업로드 화면 캡처로 겹침을 반드시 확인.
8. **믹스**: 음성 1.0 + 합성 비트 0.11, `loudnorm`(-14 LUFS 목표).
9. **영어 버전**: `scripts/dialogue/<id>_en.json`에 `"lang":"en"` 지정. `build_voice.py`가 영어 모델 설정(Supertonic `lang=en`, 화자 A=0 여성, B=5 남성)과 `en_text.py`(num2words로 숫자·%·서수 읽기 확장), 영어 ASR(`sherpa-onnx-streaming-zipformer-en-2023-06-26`)로 품질 선택을 처리한다. 두 화자의 자연 속도를 측정해 같은 속도로 맞추고 여성을 약간 느리게 한다. 화면은 `SemisEn.tsx`/`AiEn.tsx`처럼 문구만 번역한 파일로 분리하고 `LangCtx`(화자 이름·출처 접두어·자막 청크 길이)를 `Short`에 `lang={EN}`으로 넘긴다.
10. **목소리 선택 기준**: 후보를 같은 문장·같은 속도로 녹음해 사용자가 직접 듣고 고르게 한다(`scripts/voice_samples.py`). 같은 속도에서 ASR 오차율로 안정성을 비교한다(낮은 속도에서 단어를 건너뛰는 스타일은 제외). Supertonic 3 한국어는 남성 5번이 가장 안정적이었다.
